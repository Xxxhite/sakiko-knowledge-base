# 字段字典

`data/kb.json`是总入口，符合`schema/kb.schema.json`（JSON Schema Draft-07）。分表JSON和同名JSONL来自同一批记录。

| 字段 | 含义 |
|---|---|
| id | 稳定记录ID；F事实、R关系、T事件、I推断、Q待核验、S来源、E证据 |
| layer | canon / inference / fanon |
| subject_id / object_id | 指向entities的主体/对象 |
| predicate | 可供程序筛选的关系或属性名称 |
| statement_zh / title_zh | 中文命题或事件标题 |
| value | 事实的结构化值；可为字符串、数值、布尔、数组或null |
| evidence_ids | 指向evidence；证据再链接sources与原始URL |
| continuity | 所属媒介/信息域，避免把游戏档案或现实制作信息当作某集剧情 |
| valid_time / story_time | 相对剧情阶段，未知日历日期为null |
| reveal | 信息披露作品、集数、时间码；梗概定位的集数单独解释 |
| direction | directed单向，symmetric对称 |
| relation_kind | interpersonal人物、affiliation组织关联、production制作关系 |
| status | phase_scoped阶段关系、historical_fact历史事实、kinship亲属关系 |
| valence | unspecified未定；supportive_action当次支持行为；conflict当次冲突 |
| narrative_scope | diegetic剧情内，real_world_production现实制作 |
| group_context | 乐队语境的实体ID或null |
| verification_status | direct_text_verified直接正文；indexed_text_verified检索正文 |
| evidence_status | official_explicit官方直接陈述；curator_reasoning编者推理 |
| published_on / checked_on | 现实发布日期与核验日期，和剧情日期分开 |
| basis_record_ids | 推断/二创参考的既有记录 |
| worldline_id | 二创世界线标识 |

entities.name_zh与中文别名为检索显示映射；原名优先保存日文/英文。实体表只作索引，事实表与关系表承载具体命题。日期使用ISO格式，编码为UTF-8，无BOM。JSONL每行是一个完整JSON对象，空库为零行文件。

## v1.2新增字段

- candidate_claims：二手待核验命题；candidate_layer为拟归层，default_retrieval_eligible固定false。
- scene_reviews：待核问题、相关实体/证据/记录、验收标准、原片位置。
- access_audit：登录/地区/仅元数据等实际访问结果与读取范围。
- catalog_duration_minutes：平台目录按分钟标示的片长；runtime_precision=catalog_minutes。
- playback_link_evidence_ids、access_audit_ids：剧集入口与访问审计的独立出处。

## v1.3联动篇字段

narrative_level区分城堡外层、自身/队友梦、回放与梦中记忆；assertion_kind区分行动、发言、内心、旁白、其他角色主张；speaker保留说话人，subject_id为行动/发言主体，focus_entity_id固定sakiko。spoiler_rank为1—16进度，client_cross_checked当前为false；knowledge_change_zh保存明确的知情转折。relationship为场景关系，导出为game_relations。

## v1.5：开篇、覆盖与上下文

- `game_story_records.stage` 新增 `SS-ST-1`，`segment` 新增 `NBT`；街头片段用 `opening_street_vision`，其原文表现保留为独立叙事层。
- `spoiler_rank=0` 表示可在序章进度读取的街头片段。最初罗德岛梦境的性质在 SS-1 行动后明确，相关记录继续使用至少2级门槛。`--max-stage` 支持 `SS-ST-1`、`SS-TR-1`，二者对应0。
- 可选 `context_record_ids` 是阅读导航，引用较早或同剧透等级的主线记录；已有记录的事实正文和证据含义保持原样。
- `game_scene_coverage` 为第20个集合，含段落顺序、角色是否在该段文本出现、带祥子姓名的发言行数、复核范围、证据与收录记录。`text_assets` 保存固定版本来源ID、原始字节SHA-256和UTF-8文本行数，原文留在工作目录。
- `full_text_reviewed` 为所列文本全文阅读；`character_passages_reviewed` 为角色对话和相关叙述复核。两者均与客户端、配音和画面核验分开。
- `absent_in_text` 仅指列明段落的文本出场状态；该段可收录理解祥子行动所需的其他角色背景，实际主体仍为该角色。
- 覆盖审计、问答导航和阅读关联用于检索编排，默认事实片段仍只含主线、补充材料及单列解读。

## v1.6：语音与材料覆盖

| 字段 | 用途 |
| --- | --- |
| material_owner_id | 档案、模组或语音所属角色；与实际行动主体分开 |
| voice_metadata.char_word_id / voice_id / voice_asset | 原始语音行标识、语音槽位和资源键 |
| voice_metadata.place_type | HOME_WAIT、LOSE、BIRTHDAY等原始触发位置 |
| voice_metadata.unlock_type / unlock_params | DIRECT／AWAKE／FAVOR及其原始数值参数；精英化参数保留两个整数 |
| voice_metadata.text_languages_verified | 已逐项阅读的文本语言，本轮为zh-Hans和ja |
| voice_metadata.localization_evidence_ids | 指向日文对照核验笔记 |
| voice_metadata.audio_reviewed | 是否实际播放音频，当前严格为false |
| delivery_metadata | mail_id、CN服务器、Unix时间、+08:00现实发信时间；date_kind固定real_world_event_delivery |
| game_material_coverage | 第21个集合，目录、审阅槽位、相关记录及原始来源字节哈希 |
| text_assets.byte_count | 补充材料原始下载文件的字节数，与sha256配合保留版本定位 |
| thread_id / phase_group / order_within_thread | 关系主题、相对阶段及阅读次序，时间值仍沿用原场景 |

材料阶段新增MODULE_OTHER、EVENT_LETTER、EVENT_HALL、OUTFIT、ITEM、CONTRACT及对应片段标签。补充材料保持16级剧透门槛；各类叙事层按检索规则中的映射使用。稳定ID允许有间隔；去重候选未发布时已合并，后续新增取现存最大编号之后。

## v1.7：语言对照与版本归属

game_localization_checks为第22个集合，用lookup_key将同一语音槽位、档案章节、模组或来信的中日英文对应。variants保存server、language、source_id、evidence_id、locator、label、summary_zh和asset_sha256。assessment为equivalent_core、wording_variant、localized_addition，分别表示核心相符、措辞差异和语言新增段。

game_lore_records可选localization_check_ids回链对照。记录server与language必须按CN/zh-Hans、JP/ja、Global/en匹配；statement_zh始终是中文编录摘要。日服独有段落单列JP/ja记录。voice_metadata.text_languages_verified扩展en，音频核验状态继续独立保存。

检索片段保留server、language、localization_check_ids与localization_notes。差异说明携带对照证据和来源URL；有差异版本的证据保存在对照表，各自主张按版本使用。对照表作为审计材料排除默认事实片段。CN_009等原始槽位键与正文语言是两个独立字段。

## v1.8：讨论导航

game_discussion_guides为第23个集合。id为AKD三位编号；question_zh与keywords用于发现导航；record_ids列出全部正文依据。answer_outline各步保存summary_zh与record_ids；spoiler_rank取所有依据的最大值；reviewed_on为提纲复核日期。guide_kind固定curator_navigation，default_retrieval_eligible固定false。提纲的引用集合必须与总record_ids一致，校验由check_v18.py完成。

上下文工具输出是即时派生结果，未作为新的事实集合保存。字段、过滤范围和缺项语义见明日方舟检索使用规则v1.8节。

## v1.9：回答验收与维护阶段

game_answer_reviews为第24集合，ID为AKA三位编号。guide_id关联讨论导航；answer_sentences各句保存text_zh、record_ids和人工review_result=supported。record_ids为句子依据的并集；spoiler_rank覆盖全部依据；review_method=single_editor_evidence_check表明同一编者对照复核；review_note_zh保存判断与修订，review_status=passed、reviewed_on记录结论和日期，default_retrieval_eligible固定false。

自动检查验证引用与上下文，语义复核由编者进行。样本管理字段不代表客户端、音频或独立复核已完成。样本排除事实片段。

metadata可选maintenance保存active_focus（bang_dream_original/arknights_collab）、game_text_status（in_progress/text_reference_complete）、game_answer_review_ids和delivery_mode（repository_only/repository_and_archive）。这些是项目维护状态。

episode_catalog允许Ave Mujica第1—13话。runtime_precision=catalog_minutes时要求正整数catalog_duration_minutes；not_reviewed时要求该值null。新入索引但未查播放目录的条目，official_playback_url、字幕和时间码保持null。

## v1.10：作品集数与原作问答

episode_catalog新增必填work_id，取bang_dream_its_mygo或bang_dream_ave_mujica。EP两位编号绑定Ave Mujica，MYGO两位编号绑定MyGO；work_id与episode的组合唯一。announced_broadcast_date与press_release_date允许null；官方博客发布时间保存于sources.published_on，页面日期与剧情日期继续分开。

original_question_index为第25集合，id为BQ三位编号，含question_zh、keywords、record_ids及default_retrieval_eligible=false。用于原作查询导航，正文片段仍只由facts、relations、timeline、inferences构成。search_base.py按continuity及phase前缀过滤，返回citations定位；主创解读使用既有interpretation_author与inference字段。

## v1.11：订正版与剧中创作归属

监督访谈S115使用出版社2024-12-20发布的在线订正版，access_note保存原刊与采用版本的日期；checked_on为实际阅读日期。F077的diegetic_composed_song表示故事内作曲归属。艺名词源F079与心理解释I008分开，I008／I009的interpretation_author分别为监督和声优，基础检索text同时保留解读者。F074补E439并保留E429的末段集数定位。
