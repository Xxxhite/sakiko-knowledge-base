# 明日方舟剧情检索使用规则

用户提到明日方舟、无忧梦呓、泰拉、梦城堡或莫菲丝时，优先检索continuity=arknights_collab，焦点实体为sakiko。默认layer=canon；分析成长、动机等问题时可另取inference，并在回答中明示解读归属。

直接导入jsonl/game_retrieval_chunks.jsonl即可建立联动剧情检索集合；同时使用原作资料时，导入retrieval_combined.jsonl。retrieval_chunks.jsonl保留原格式，当前为123条基础检索记录，合并316条。不要重复导入三份文件。game_question_index提供常见问法与记录ID映射。

## 回答应带的上下文

先说明具体行为或台词，再按用户需要解释。引用定位用关卡、行动前/后、场景和原始URL。第三人称评价保留说话人；梦境、回放、内心字幕与城堡外层分别按narrative_level使用。跨世界线比较时分别引用两组材料。

canon层表示原作内容性质；game_text_transcription是证据取得状态，表示已读取社区承载的游戏文本，client_cross_checked=false。需要官方站直接资料时筛official_only_eligible；剧情转录不具有此资格。

莫菲丝的攻击性评价标other_character_claim，引用时写“莫菲丝指责……”。梦中“母亲”与带引号的“睦”使用独立节点。最初罗德岛同行段按initial_sakiko_dream记录，梦境性质在SS-1行动后披露；两处事实由spoiler_rank共同控制。

## 剧透与时间

spoiler_rank按关卡行动前/后排列1—16。调用方可给max_spoiler_rank，只返回不超过已读进度的内容。记录的scene_order是稳定条目顺序，实际阅读按stage与segment排序；事件日历日期和视频时间码均为空。

## 本地检索

附带Python 3标准库检索工具tools/search_game.py，支持中文关键词/双字片段、分层、关卡进度及官方来源过滤。它返回可供回答的资料和来源，不生成新剧情。运行方式见README。接入聊天应用或向量库时，由应用执行检索并把结果放入对话上下文。

## v1.4补充材料

game_lore_records独立保存档案、晋升、模组和语音，narrative_level=post_castle_rhodes_island，spoiler_rank统一16。material_type可筛main_story/operator_file/promotion_record/module_story/voice/interpretation。v1.4的空触发标签已在v1.6按固定版本语音表补齐，完整条件见语音目录。

character_guess用于角色自己的猜想：例如AKL010的小提琴手猜测；future_plan用于尚未表现为完成的计划。SC004保留人偶赠送者的两处表述，回答该主题时同时读取AKL009、AKL016。

## v1.5开篇与覆盖

序章幕间为SS-ST-1 / NBT。街头片段使用opening_street_vision，剧透等级0；随后罗德岛梦境使用initial_sakiko_dream，标签披露仍设在SS-1行动后。检索进度新增SS-ST-1、SS-TR-1两个0级入口。

SS-2行动前的AK075、AK076以若麦为实际主体，用于补足祥子后续劝醒她的背景；覆盖表记录祥子在该段未出场。context_record_ids提供较早或同进度记录的补取导航，与来源差异所需的required_context_record_ids分别使用。

game_scene_coverage含18个段落、复核范围、出场状态、证据及固定文本哈希，作为管理数据保存。该轮曾有110条联动检索片段、合并229条；v1.6已更新为192／311条。更新联动数据后可运行tools/export_game.py同步镜像与对应视图，基础检索标签另行维护。

## v1.6语音、队友与附加材料

material_type新增event_letter、event_interface、outfit_description、item_description、operator_contract。保持全部补充材料spoiler_rank=16；服装文字用costume_description或dream_costume_description，来信用event_hall_correspondence，大厅规则用event_interface。档案、模组与语音继续用post_castle_rhodes_island。

material_owner_id表示材料所属角色，与实际主体subject_id分开。例如睦档案中祥子的嘱托以sakiko为主体、mutsumi为材料所有者。每个具名评价保留说话人。

voice_metadata保留原始charWordId、voiceId、voiceAsset、placeType、unlockType及数值参数，中文与日文正文核对状态单列；音频未播放，audio_reviewed保持false。DIRECT为资源的解锁类型，节庆语音仍按place_type区分新年、生日和周年。

delivery_metadata保存国服现实活动发信时间与时区；event_calendar_date继续表示作品内日期。新集合game_material_coverage保存目录审计，排除默认事实检索。

关系视图可按thread_id与phase_group组织，order_within_thread是阅读次序。梦中认识、城堡外层初见、罗德岛日常及来信支持分别查询。阶段内的档案／语音并无统一精确时间顺序。

## v1.7：语言对照与版本归属

game_localization_checks为第22个集合，用lookup_key将同一语音槽位、档案章节、模组或来信的中日英文对应。variants保存server、language、source_id、evidence_id、locator、label、summary_zh和asset_sha256。assessment为equivalent_core、wording_variant、localized_addition，分别表示核心相符、措辞差异和语言新增段。

game_lore_records可选localization_check_ids回链对照。记录server与language必须按CN/zh-Hans、JP/ja、Global/en匹配；statement_zh始终是中文编录摘要。日服独有段落单列JP/ja记录。voice_metadata.text_languages_verified扩展en，音频核验状态继续独立保存。

检索片段保留server、language、localization_check_ids与localization_notes。差异说明携带对照证据和来源URL；有差异版本的证据保存在对照表，各自主张按版本使用。对照表作为审计材料排除默认事实片段。CN_009等原始槽位键与正文语言是两个独立字段。

## v1.8：多段讨论与证据上下文

game_discussion_guides为第23个集合；AKD001—AKD012组织多段记录，guide_kind=curator_navigation、default_retrieval_eligible=false。answer_outline是编者提纲，每步的record_ids回链已有canon记录。导航排除事实片段；主数据与分集合JSON/JSONL同步导出，阅读视图为明日方舟_多段剧情讨论导航.md。

tools/context_game.py接收自然问题、--guide或可重复的--record。自然问题返回常规检索与最多三项相关导航建议；显式选定导航后取得其全部依据。--limit控制初始检索条数，--max-records控制展开后的总条数（默认40）。剧情背景只展开一层，来源差异关联递归闭合并去重。

material限制初始命中和普通剧情背景；required_source_issue_context可跨material补取，例如仅筛模组时仍补赠礼语音。剧透、分层与官方来源过滤适用于所有补取记录。结果的blocked_context给出spoiler_filter、layer_filter、official_filter、material_filter或record_budget；missing_required_context_ids列出已返回记录仍需但未取到的差异伙伴。required_context_complete只描述已返回记录的必要关联；guide_complete描述指定提纲是否全部取得。

每条results附citations（evidence_id、source_id、original_url、locator、language、verification_status），同时保留片段自身的场景层、说话人、语言与localization_notes。仅在指定导航的全部record_ids都已返回时显示answer_outline，防止提纲绕过进度或来源筛选。导航建议同样按剧透门槛筛选。

本轮完成编者提纲复核、12项自然问法导航发现和上下文过滤测试；生成回答评估与聊天系统接入仍为后续步骤。

12项实际回答样本、30句已按记录、来源差异及选取的固定文本核对，保存于game_answer_reviews及明日方舟_问答验收.md。该集合为编者回答样本与审阅记录，排除193条正文／解读检索片段。check_v19.py只自动核验结构、引用和上下文可用性；句意判断见review_note_zh。

游戏文本按讨论检索用途收尾。客户端、音频、画面、赠礼过程、匿名听众与语言版本显示继续长期维护；当前主建设方向已回到原作。
