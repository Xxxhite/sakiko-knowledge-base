# 明日方舟剧情检索使用规则

用户提到明日方舟、无忧梦呓、泰拉、梦城堡或莫菲丝时，优先检索continuity=arknights_collab，焦点实体为sakiko。默认layer=canon；分析成长、动机等问题时可另取inference，并在回答中明示解读归属。

直接导入jsonl/game_retrieval_chunks.jsonl即可建立联动剧情检索集合；同时使用前版本资料时，导入retrieval_combined.jsonl。旧retrieval_chunks.jsonl保留原格式，仍为119条基础检索记录。不要重复导入三份文件。game_question_index提供常见问法与记录ID映射。

## 回答应带的上下文

先说明具体行为或台词，再按用户需要解释。引用定位用关卡、行动前/后、场景和原始URL。第三人称评价保留说话人；梦境、回放、内心字幕与城堡外层分别按narrative_level使用。跨世界线比较时分别引用两组材料。

canon层表示原作内容性质；game_text_transcription是证据取得状态，表示已读取社区承载的游戏文本，client_cross_checked=false。需要官方站直接资料时筛official_only_eligible；剧情转录不具有此资格。

莫菲丝的攻击性评价标other_character_claim，引用时写“莫菲丝指责……”。梦中“母亲”与带引号的“睦”使用独立节点。最初罗德岛同行段按initial_sakiko_dream记录，梦境性质在SS-1行动后披露；两处事实由spoiler_rank共同控制。

## 剧透与时间

spoiler_rank按关卡行动前/后排列1—16。调用方可给max_spoiler_rank，只返回不超过已读进度的内容。记录的scene_order是稳定条目顺序，实际阅读按stage与segment排序；事件日历日期和视频时间码均为空。

## 本地检索

附带Python 3标准库检索工具tools/search_game.py，支持中文关键词/双字片段、分层、关卡进度及官方来源过滤。它返回可供回答的资料和来源，不生成新剧情。运行方式见README。接入聊天应用或向量库时，由应用执行检索并把结果放入对话上下文。

## v1.4补充材料

game_lore_records独立保存档案、晋升、模组和语音，narrative_level=post_castle_rhodes_island，spoiler_rank统一16。material_type可筛main_story/operator_file/promotion_record/module_story/voice/interpretation。语音trigger_label与部分unlock_condition为空，使用时以内容定位，不猜填触发条件。

character_guess用于角色自己的猜想：例如AKL010的小提琴手猜测；future_plan用于尚未表现为完成的计划。SC004保留人偶赠送者的两处表述，回答该主题时同时读取AKL009、AKL016。
